# 화면 목록 정의서 v0.2

## 1. 문서 개요

- **문서명**: 실행형 AI 개발 플랫폼 화면 목록 정의서
- **버전**: v0.2
- **목적**: 서비스의 주요 화면을 정의하고, 기능정의서와 디자인정의서의 기준 문서로 활용한다.
- **기준 방향**: 다양한 AI 모델을 선택해 대화할 수 있는 UX를 기반으로 하되, 채팅을 작업 지시의 진입점으로 사용하고, Computer와 Chrome 기반 브라우저 화면에서 AI가 리서치, 개발, 실행, 테스트를 수행하는 **실행형 AI 개발 플랫폼**으로 정의한다.

---

## 2. 제품 정의

이 서비스는 단순한 AI 채팅 앱이 아니라, 개인/팀/엔터프라이즈 사용자가 AI와 에이전트를 활용해 실제 작업을 수행하고 그 과정을 확인할 수 있도록 설계된 **실행형 AI 개발 플랫폼**이다.

- 다양한 AI 모델을 선택해 일반 대화, 리서치, 코딩 작업 수행
- 원격 Linux Computer에서 AI가 실제로 개발/실행/테스트 수행
- Chrome 기반 브라우저 화면을 통해 AI의 작업 과정을 사용자에게 가시화
- 프로젝트 중심으로 문서, 실행, 테스트, 에이전트 작업을 연결
- 단일 에이전트 기반 작업 수행, 멀티에이전트는 v1 확장으로 준비
- 팀 단위 협업, 공동 문서 편집, 공동 프로젝트 개발 지원
- 향후 결제/구독 확장이 가능한 플랜 구조 운영

### 핵심 경험 원칙

- 채팅은 출발점이며, 핵심 가치는 AI가 실제로 작업을 수행하는 실행 경험에 있다.
- AI는 답변만 생성하는 것이 아니라, 격리된 Computer와 브라우저에서 검색, 개발, 실행, 테스트를 수행한다.
- 사용자는 결과뿐 아니라 AI의 브라우저 행동, 실행 로그, 테스트 과정을 함께 본다.
- 브라우저 기반 검증은 선택 옵션이 아니라 제품 신뢰도를 만드는 핵심 UX다.
- 프로젝트는 실행의 중심 단위이며, 채팅과 문서는 프로젝트 작업을 보조하는 구조로 설계한다.
- 개인/팀/엔터프라이즈 모두를 고려해, 권한/승인/보존/정책 적용 범위가 UI에서 설명 가능해야 한다.

## 3. 사용자 유형

| 사용자 유형 | 설명 |
|---|---|
| Personal User | 개인 워크스페이스에서 채팅, 문서, 프로젝트, 에이전트 사용 |
| Team Member | 팀 워크스페이스에서 팀 문서/프로젝트/에이전트 협업 |
| Team Admin | 팀원 초대, 역할 관리, 팀 프로젝트 및 사용량 일부 관리 |
| Team Owner | 팀 최고 권한, 좌석/플랜/소유권을 포함한 팀 운영 관리 |
| Enterprise Admin | 조직 단위 정책, SSO, 감사로그, 보안 관리 |
| Platform Admin | 전체 서비스 운영, 모델/실행 인프라/플랜/사용자/분석 관리 |

### 비고

- `Platform Admin`은 전역 운영 관리자 역할의 상위 개념이며, 실제 운영에서는 `Super Admin`, `Support Admin`, `Billing Admin`, `Security Admin`처럼 세분화될 수 있다.

### CHAT-01 AI 채팅 메인

#### 목적

- 모델과 대화하며 작업을 정의하고, Computer/브라우저 기반 실행을 시작하는 진입 화면

#### 핵심 기능

- 새 대화 생성
- 모델 선택
- 모델 capability/role badge 표시(`chat`, `coding`, `reasoning`, `research`)
- 작업 모드 선택(일반 대화 / 리서치 / 개발 / 테스트)
- 메시지 스트리밍
- 파일 첨부
- 프로젝트 또는 문서 컨텍스트 연결
- 에이전트 실행 요청
- Computer 세션 시작 또는 기존 세션 연결
- 결과물 저장 또는 프로젝트 반영

#### 주요 컴포넌트

- 대화 리스트
- 메시지 영역
- 모델 선택기
- 작업 모드 선택기
- capability / 제한 사유 badge
- 입력창
- 첨부 파일 영역
- 컨텍스트 패널

#### 상태

- 응답 생성 중
- 중단됨
- 도구 실행 중
- 플랜 제한
- 토큰/사용량 초과
- 모델 접근 불가
- 추론 모델 또는 reasoning parameter 제한

#### 비고

- 이 화면은 제품의 입구이지만, 제품의 본체는 실행형 작업 흐름이라는 점이 구조적으로 드러나야 함

- OpenWebUI 수준의 세밀한 운영 설정을 실제로 조회/수정

#### 핵심 기능

- General, Connections, Models, Documents & Retrieval, Web Search 설정
- Computer & Browser, Code Execution, Agents 설정
- Audio, Images, Integrations, Pipelines 설정
- Billing & Plans, Security & Audit, Database & Data Ops 설정
- 저장 전 검증과 연결 테스트
- 적용 범위, 보존 정책, 승인 영향, 감사 이력 확인

#### 주요 컴포넌트

- 카테고리 2차 내비게이션
- 설정 카드/폼 그룹
- Save / Save & Test 바
- 변경 이력 보조 패널
- Danger Zone
- 적용 범위/보존/승인 메타 패널

#### 비고

- 세부 카테고리별 구조는 `docs/admin-screen-definition-v0.1.md`와 `docs/admin-panel-spec-v0.1.md`를 기준으로 확장함
- `ADMIN-07`은 부모 화면 ID이며, 실제 세부 화면은 `ADMIN-07-01`부터 `ADMIN-07-17`까지의 하위 설정 화면으로 분해 가능함

## 10. 모바일 대응 원칙

- 모든 핵심 기능은 모바일에서 접근 가능해야 함
- 좌측 사이드바는 드로어 UI로 전환
- 우측 정보 패널은 바텀시트 또는 탭 패널로 전환
- 채팅 입력창은 모바일에서 하단 고정
- 프로젝트 상세의 복잡한 정보는 탭 분리 필요
- Computer 화면은 모바일에서 브라우저 / 터미널 / 로그 / 프리뷰를 분리 탭으로 제공
- 문서 편집기는 모바일에서 읽기/편집/댓글 모드 분리 고려
- 긴 표와 로그는 가로 스크롤 또는 카드 구조로 대응
- 관리자 화면은 모바일에서도 확인 가능해야 하지만, 조작은 데스크톱 최적화 기준으로 설계

## 11. 디자인정의서로 넘길 핵심 포인트

- 각 화면마다 반드시 아래 상태를 디자인해야 함
  - 빈 상태
  - 로딩 상태
  - 오류 상태
  - 권한 없음
  - 사용량 초과
  - 플랜 업그레이드 유도 상태
- 협업 화면은 아래 요소를 반드시 시각화해야 함
  - 공유 범위/참여자 요약
  - 현재 접속자 또는 최근 활동자
  - 최근 변경
  - 승인/리뷰 상태
- Computer 및 에이전트 화면은 아래 요소를 반드시 보여야 함
  - 실행 상태
  - 브라우저 화면
  - 액션 타임라인
  - 진행률
  - 로그
  - 결과물
  - 실패 원인
  - 정책 제한 이유
  - 승인 필요 여부
  - 보존/저장 상태
- 실행형 화면은 아래 승인 상태도 명확히 표현해야 함
  - 사용자 승인 대기
  - 브라우저 제어 중
  - 테스트 실패
  - 재실행 가능
- 관리자/엔터프라이즈 화면은 아래 거버넌스 요소를 반드시 시각화해야 함
  - 적용 범위와 override source
  - 감사 링크와 최근 변경자
  - 보존 기간과 만료 영향
  - 권한/SSO/정책의 현재 유효 상태
- 플랜/사용량 영역은 단순 설정이 아니라 아래를 명확히 보여야 함
  - 기능 제한
  - 좌석 수
  - 사용량
  - 업그레이드 여지
- 채팅, 프로젝트, 문서, 에이전트, Computer, 브라우저가 서로 연결되는 구조를 IA에서 명확히 표현해야 함
- 디자인 위계는 `채팅 SaaS`보다 `실행형 워크스페이스`처럼 느껴지도록 잡아야 함

## 12. 비고

- 본 문서는 화면 목록 기준의 초안이며, 상세 기능 우선순위와 API 설계는 `docs/core-api-priority-v0.1.md`, `docs/screen-api-mapping-v0.1.md`에서 이어서 관리한다.
